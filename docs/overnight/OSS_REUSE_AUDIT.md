# Архивный аудит повторного использования OSS

> Исторический технический аудит. Зафиксированные версии upstream/dependencies и выводы относятся к указанным в разделах датам и могут устареть; перед новой зависимостью перепроверьте официальный source. Актуальные общие правила — в [`CONTRIBUTING.md`](../../CONTRIBUTING.md) и [`ADR-001`](../../decisions/ADR-001-office-kit-renderer-spike.md). Исходные технические выдержки сохранены на языке их первоисточника.

**Reviewed:** 2026-09-26 at LCT `1d063b4ea70861bb488dfa87304a8e0d24905aea`. This is a source-level reuse audit; none of the donor projects was installed or run. No dependency or copied code was added.

## Current LCT capabilities to preserve

LCT already has a deterministic PPTX inspection path, `TemplateIR`/`PresentationDesignSystem`, measured template candidate selection, an exemplar projection path, native PPTX rendering behind adapters, `ContentIR`/`DeckPlan`, source references, deterministic audit, bounded repair, and SQLite persistence. The reusable implementation priority is to correct the measured case-template failures in those paths. A second parser, model adapter, renderer, agent framework, or persistence stack would add integration risk without fixing the current blocker by itself.

| Idea | Decision | Gap/benefit vs LCT | Integration cost, dependencies, license |
|---|---|---|---|
| Template slides as a component library; semantic named slots | **ADAPT CONCEPT** | Clear slot names and role-specific render dispatch help describe a curated internal deck. This donor's templated path opens its own six-slide `academic-editorial.pptx`, hardcodes `ROLE_TO_LAYOUT_IDX`, and depends on named shapes. It is not a general corporate-template parser. LCT already measures roles and projects selected real exemplars; importing its fixed role map would repeat the wrong abstraction and risks a one-template design. | Do not copy the renderer. The `clone_template_slide` implementation manipulates private `python-pptx` shape-tree fields and explicitly does not copy picture relationships; the donor template is expected to be picture-free. The LCT runtime is TypeScript/Office Kit. MIT is present, but see provenance note below. |
| Archetype dispatch | **ADAPT CONCEPT** | The four shipped renderers (`cover_editorial`, `evidence_snapshot`, `takeaway_list`, `thanks_qa`) show how content intent can select a renderer; six other labels are placeholders that fall through to default. The useful idea is that intent selects a candidate family, then fit/safety decides whether it can render. LCT's selector already does this with its own template evidence. | No new archetype layer or transplanted enum. Keep any future changes inside the current selector and renderer boundary; retain measured fit/withhold behavior. |
| Critique rubric and narrative/provenance checks | **ADAPT CONCEPT** | The deck critic explicitly checks factual provenance, visual hierarchy, typography, layout, narrative flow, and claim coverage; it requires evidence anchors and has a capped verdict/revision path. This maps well to Appendix 1's semantic questions and LCT's current title/summary/narrative failures. LCT already checks exact source IDs and numeric/table/chart refs, but not entailment, takeaway strength, or complete narrative coverage. | Reuse criteria as a review checklist, not the prompt or agent code. Donor rubric assumes paper raw text/ClaimGraph and a vision critic's tool API; LCT uses `ContentIR` source refs and a different bounded Supervisor contract. Do not create a second agent framework. |
| Claim graph / provenance coverage | **ADAPT CONCEPT** | A slide-to-claim coverage map could expose missing required source ideas and narrative gaps; exact numeric refs alone cannot establish that all important claims were covered. Use only after the WorkSpace visual-fit blocker. | Keep IDs anchored to existing `ContentIR`/`DeckPlan`; no donor schema. Validate on an actual case pack before deciding to implement. |

**License/provenance:** the root [`LICENSE`](https://github.com/EthanGuo2022/OpenDesign/blob/7dee599ca39a7c164351e7d637c2b5a24ca23842/LICENSE) says MIT and names Yaxin Luo; bundled fonts are separately marked OFL 1.1. The architecture, decision log, and roadmap describe an artifact-type-dispatched poster/landing/deck toolchain; they do not add a generic corporate-PPTX template contract. This static audit did not test installation or execution.

| Idea | Decision | Gap/benefit vs LCT | Integration cost, dependencies, license |
|---|---|---|---|
| Theme, master, layout, placeholder extraction | **SKIP dependency** | It extracts scheme colors, theme fonts, backgrounds, placeholder type/position/style, master definitions, and generates `PptxGenJS` code. ## Decision summary

- **REUSE CODE:** none in this run. No donor code passes the combined identity/architecture/compatibility gate for LCT's current blockers.
- **ADAPT CONCEPT:** bounded critique criteria and claim/provenance coverage from EthanGuo2022/OpenDesign; role-to-renderer dispatch as a check on the existing selector; conditional color-modifier algorithm only if actual template evidence proves a color gap.
- **SKIP:** Pandemonium's token-ingestion app, flat deck schema, PptxGenJS export/UI; `pptx-masters` as a dependency or second renderer; copying Ethan's fixed six-slide template path.
- **Why not reuse a ready PPTX mechanism?** Current code already uses Office Kit, TemplateIR/PDS, measured exemplar selection, rendering, package inspection, and audit. The observed blockers are LCT-specific candidate safety/body-role fit, semantic title/narrative quality, preview overflow, and missing product export/audit paths. The inspected OSS projects do not provide a drop-in solution to those issues.
