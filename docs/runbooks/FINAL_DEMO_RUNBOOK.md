# Финальный demo runbook

Локальный демонстрационный путь использует fake semantic endpoint. Он показывает подготовку шаблона, план, варианты, аудит и экспорт, но не выдаёт ответы fake endpoint за результат Qwen.

## Запуск на Windows

Требования: Node.js 24, Python 3.12 и зависимости проекта. Из корня репозитория:

```powershell
pnpm dlx pnpm@10.33.2 install --frozen-lockfile
```

`.env.example` задаёт следующие безопасные loopback-параметры; секретов в нём нет:

| Переменная | Значение |
|---|---|
| `LCT_BIND_HOST` | `127.0.0.1` |
| `LCT_WEB_HOST` | `127.0.0.1` |
| `LCT_PORT` | `7456` |
| `PORT` | `3000` |
| `LCT_DATA_DIR` | `.lct` |
| `LCT_FAKE_SEMANTIC_PORT` | `8787` |
| `LCT_SEMANTIC_BASE_URL` | `http://127.0.0.1:8787/v1` |
| `LCT_SEMANTIC_MODEL` | `Qwen/Qwen3.8-27B` (только отображаемый alias для fake endpoint) |
| `LCT_SEMANTIC_ENABLE_THINKING` | `false` |
| `LCT_PPTX_BACKEND` | `office-kit` |

Откройте два PowerShell-терминала в корне репозитория.

Терминал 1 — локальный fake endpoint:

```powershell
node --env-file=.env.example scripts/dev-fake-semantic-endpoint.mjs
```

Терминал 2 — daemon и web:

```powershell
node --env-file=.env.example scripts/dev.mjs
```

Откройте `http://127.0.0.1:3000`. Остановка: `Ctrl+C` в обоих терминалах. Если порт `8787` занят, измените одновременно `LCT_FAKE_SEMANTIC_PORT` и порт в `LCT_SEMANTIC_BASE_URL`.

## Демонстрационный шаблон и бриф

Для основного показа используйте проверенный файл VK WorkSpace `VK_WorkSpace_Клиентская_конференция_Шаблон_03.pptx`. В UI выберите его как шаблон. Исходные материалы добавлять не требуется: это режим «задача и бриф без source package».

Бриф для поля задачи:

> Для руководителей: подготовь краткую презентацию о компании, её направлениях и клиентах. Покажи проблему и решение, сегменты аудитории, структуру направлений, путь клиента, рабочий процесс, роли системы, контроль качества, архитектуру и итоговую ценность. Не добавляй неподтверждённые цифры, даты или результаты. На каждом слайде — выводный заголовок и до трёх коротких тезисов.

Укажите 10 слайдов. Без загруженного content package LLM-сформулированный текст имеет provenance «создано по брифу»; он не является подтверждённым исходными материалами фактом.

## Сценарий показа

1. Создайте проект и загрузите шаблон. Ожидаемое состояние: файл принят, начинается анализ.
2. Дождитесь статуса «Шаблон готов». Откройте инспектор и покажите найденные макеты и оформление. Подготовка профиля завершается до основного таймера.
3. Введите бриф и число слайдов `10`; нажмите «Сгенерировать план». Ожидаемое состояние: план готов к просмотру.
4. Проверьте порядок и заголовки плана; нажмите «Сгенерировать варианты». **Пятиминутный таймер запускайте в момент этого нажатия**, а не во время загрузки шаблона или его предварительного анализа. Остановите замер, когда все A/B/C варианты готовы и доступны в редакторе.
5. Переключите A/B/C на нескольких слайдах. Это должно менять реальные предпросмотры; выбор варианта не запускает планирование повторно.
6. Откройте «Проверка презентации». Покажите contextual findings и детерминированный аудит отдельно. Исправление применяйте только по конкретному замечанию, затем повторно проверьте выбранный вариант.
7. В блоке экспорта скачайте выбранную презентацию: PPTX — редактируемый файл; PDF и HTML — форматы просмотра. При необходимости отдельно выгрузите A/B/C.

## Сбои и безопасный запасной путь

- `INVALID_STRUCTURED_OUTPUT`: не показывайте частичный план как готовый. Используйте ограниченную кнопку повтора, если UI её предлагает; при повторной ошибке остановитесь и сохраните технический код для диагностики.
- `SERVICE_UNAVAILABLE`: проверьте доступность настроенного endpoint и не запускайте повторные запросы серией. Для локальной репетиции вернитесь к fake-конфигурации из `.env.example`.
- Contextual audit недоступен: покажите его состояние как недоступное, не называйте проверку пройденной. Детерминированный аудит остаётся отдельным результатом; завершённую генерацию не следует выдавать за contextual PASS.
- Экспорт не готов: не скачивайте ранее созданный файл как будто он соответствует новому плану. Вернитесь в редактор, убедитесь, что выбранные варианты актуальны, и повторите экспорт через UI.

## Измерения и границы доказательств

- Реальная WorkSpace template preparation заняла `875,423 ms` и завершилась с persisted profile `READY`. Она предшествует нажатию «Сгенерировать варианты» и не входит в официальный пятиминутный замер. Источник: [план квалификации неизвестного шаблона](../plans/active/unknown-template-preparation-demo.md).
- Единственное записанное real-Qwen измерение A/B/C: 3 слайда, 9/9 вариантов готовы за `10.88 s`, детерминированный аудит без ошибок. Последующий contextual audit вернул `INVALID_STRUCTURED_OUTPUT`; полный успешный live flow и 10–15-слайдовый latency не подтверждены. Источник: [план generated-copy qualification](../plans/active/task-only-generated-copy.md).
- Fake WorkSpace, held-out и Education прогоны подтверждают только offline интеграцию. Их времена нельзя приводить как Qwen/VK latency или как выполнение лимита 300 секунд.

## Когда останавливать RunPod

Для будущей ограниченной live-квалификации держите Pod запущенным только на время заранее разрешённого workflow. Останавливайте его вручную **после** завершения semantic/profile и planning вызовов, генерации, contextual audit и локальной проверки экспортированных файлов, когда больше не требуется обращаться к endpoint. Не останавливайте Pod во время активного запроса или между этапами одного согласованного workflow. В этом integration pass RunPod и live endpoint не использовались.
